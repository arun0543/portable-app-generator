# ADR-0001

# Project Architecture

Status

Accepted

---

# Context

Portable App Generator will become a reusable framework capable of supporting many portable applications.

The architecture must remain maintainable as the project grows.

A monolithic Bash script would become difficult to test, maintain, and extend.

---

# Decision

Adopt a modular architecture.

The generator consists of independent modules located under

lib/

Each module owns one responsibility.

Examples

Logger

Validator

Filesystem

Desktop

Launcher

Profile

Plugin Loader

Configuration

Rollback

Backup

---

# Alternatives

Single Bash Script

Rejected

Reason

Poor maintainability.

Hard to test.

Hard to extend.

---

Application Specific Generator

Rejected

Reason

The framework must support many applications.

---

# Consequences

Advantages

High maintainability

Easy testing

Reusable modules

Plugin friendly

Simple debugging

Git-friendly commits

Disadvantages

More files

Higher initial complexity

---

# Notes

Every module should expose a documented public API.

Cross-module dependencies should remain minimal.
